# Platform rules | Regole per piattaforma

Platform adapters must document supported page shapes, permissions, visible fields, known limitations, terms/policy assumptions and fixture sources. An adapter must not depend on private APIs, bypass access controls or automate transactions.

Gli adapter di piattaforma devono documentare forme pagina supportate, permessi, campi visibili, limitazioni note, assunzioni su termini/policy e fonti delle fixture. Un adapter non deve dipendere da API private, aggirare controlli di accesso o automatizzare transazioni.

The first planned adapter is Vinted. This directory intentionally contains no selectors until the adapter work begins and its permitted interaction model is checked.

Il primo adapter pianificato e Vinted. Questa cartella non contiene intenzionalmente selector fino all'inizio del lavoro sull'adapter e alla verifica del suo modello di interazione consentito.

## Policy-pack rule | Regola dei policy pack

Marketplace rules, alleged illegal-content notices, intellectual-property complaints, post-purchase disputes and immediate safety emergencies are distinct routes. Every pack must cite official first-party sources, record locale and reviewed date, define applicability and return a stale state after its review window. See [official-source research](../research/legal-platform-reporting-and-llm-integrations.md) and [reporting playbooks](../reporting-playbooks/README.md).

Regole marketplace, segnalazioni di presunto contenuto illegale, reclami di proprieta intellettuale, controversie post-acquisto ed emergenze di sicurezza immediate sono percorsi distinti. Ogni pacchetto deve citare fonti ufficiali primarie, registrare lingua o area e data di revisione, definire applicabilita e restituire stato obsoleto dopo la finestra di revisione. Vedere [ricerca su fonti ufficiali](../research/legal-platform-reporting-and-llm-integrations.md) e [guide alla segnalazione](../reporting-playbooks/README.md).
